# BOS Bot v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a signed-capable personal macOS BOS Bot desktop application from pinned OpenMausBot source, branded with the BOS kit, centered on official Claude and Codex CLI subscriptions, with AIOS MCP setup and hardened local-only defaults.

**Architecture:** Start from OpenMausBot commit `ed1c15d970550e984541b4474d6731c1597c6563`, retain its Electron renderer/main/harness separation, and remove enterprise and v1-excluded hosted surfaces. Put BOS identity and feature policy behind small shared modules so upstream fixes remain reviewable. Preserve provider drivers and existing security controls, then add BOS-specific provenance, AIOS preset, regression tests, and packaged-app verification.

**Tech Stack:** Electron 43, React 19, TypeScript 5.8, Vite 7, Tailwind 4, Node 24, Vitest 4, electron-builder, official Claude CLI stream-json, official Codex app-server JSON-RPC.

---

- `shared/bos-product.test.ts` — product-policy contract tests.
- `server/bos-aios-preset.ts` — discover and validate a local AIOS MCP command without hard-coded user paths.
- `server/bos-aios-preset.test.ts` — preset discovery, disabled-by-default, and redaction tests.
- `server/drivers/bos-provider-policy.ts` — trusted executable and tested-version policy for Claude and Codex.
- `server/drivers/bos-provider-policy.test.ts` — executable/version fail-closed tests.
- `src/lib/bos-features.ts` — renderer-facing feature gates derived from the shared policy.
- `src/lib/bos-features.test.ts` — navigation and settings visibility contracts.
- `src/components/SettingsModal.tsx`, `src/components/Sidebar.tsx`, `src/App.tsx` — apply v1 surface gates without CSS hiding.
- `src/components/McpServersPanel.tsx` — offer the AIOS preset through the normal reviewed MCP mutation flow.
- `src/components/EngineLibrary.tsx`, `src/components/EngineSetup.tsx` — make Claude and Codex the primary v1 setup path.
- `src/lib/brand.ts`, `server/brand.ts` — replace upstream default identity with BOS without enterprise white-label coupling.
- `src/styles.css`, `public/*`, `build/*`, `electron/resources/*` — BOS tokens and assets.
- `electron-builder.yml`, `package.json`, `index.html` — application identity, protocol, package metadata, updater policy, and artifacts.
- `NOTICE`, `THIRD_PARTY_NOTICES.md`, `docs/provenance/openmausbot.md`, `docs/provenance/bos-brand-kit.md` — licensing and source provenance.
- `electron/main.mjs`, `electron/preload.cjs`, `electron/desktop-server-auth.cjs`, `server/index.ts` — only if the audit proves current local authorization needs changes.
- `scripts/verify-bos-package.mjs` — deterministic package identity, license, secret-pattern, and excluded-module checks.
- `scripts/verify-bos-package.node-test.mjs` — verifier fixtures.
