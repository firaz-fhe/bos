# BOS Bot v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a signed-capable personal macOS BOS Bot desktop application from pinned OpenMausBot source, branded with the BOS kit, centered on official Claude and Codex CLI subscriptions, with AIOS MCP setup and hardened local-only defaults.

**Architecture:** Start from OpenMausBot commit `ed1c15d970550e984541b4474d6731c1597c6563`, retain its Electron renderer/main/harness separation, and remove enterprise and v1-excluded hosted surfaces. Put BOS identity and feature policy behind small shared modules so upstream fixes remain reviewable. Preserve provider drivers and existing security controls, then add BOS-specific provenance, AIOS preset, regression tests, and packaged-app verification.

**Tech Stack:** Electron 43, React 19, TypeScript 5.8, Vite 7, Tailwind 4, Node 24, Vitest 4, electron-builder, official Claude CLI stream-json, official Codex app-server JSON-RPC.

---

- [ ] **Step 1: document the actual upstream storage model**

Adopt these policies and document their implementation:

- root: `~/.bos-bot` in production, overridable only by the existing test/data-dir mechanism; migrate from neither `~/.openmausbot` nor BOS superapp automatically in v1
- config/bots: owner-only JSON written through `writeFileAtomic` with backup-before-replace
- transcripts: SQLite `messages.db`, WAL mode, owner-only permissions, transactions/savepoints through `server/message-db.ts`
- attachments: content under a BOS-owned attachments directory keyed by message id; canonical paths may not escape the root
- cursors: versioned provider, protocol version, thread id, and last-confirmed-turn metadata owned by the conversation
- retention: no automatic deletion in v1; user-owned local data remains until explicit delete
- delete bot: confirmation is required; one transaction removes BOS bot metadata, local conversations/events/cursors/index rows, and BOS-owned attachments, while never deleting provider-account history; failure rolls back metadata and leaves recoverable files
- export: user-selected path, secret-redacted transcript plus copied safe attachments, written to a temporary sibling then atomically renamed
- migrations: integer schema version, pre-migration backup, bounded transaction, marker advances only after success; rollback restores the previous readable store
- crash recovery: WAL recovery plus reconciliation of attachment orphans and completion-unknown turns; side-effecting tool calls are never replayed automatically
